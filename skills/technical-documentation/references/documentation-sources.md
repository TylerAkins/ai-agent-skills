# Documentation Design Sources

Reviewed on October 13, 2026 for this skill and the collection's onboarding rewrite.
These references inform the current revision, not a verified source history for
earlier commits. Our prose and commands are authored for this repository.

| Source | Principle used |
| --- | --- |
| [GitHub collapsed sections](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/organizing-information-with-collapsed-sections) | Use native details/summary markup and blank lines so Markdown renders inside each section. |
| [Diátaxis](https://diataxis.fr/) | Separate task instructions, reference, explanation, and learning material by reader needs. |
| [Write the Docs](https://www.writethedocs.org/guide/writing/beginners-guide-to-docs/) | Give first-time readers an installation path and a usable example. |
| [Addy's README](https://github.com/addyosmani/agent-skills/blob/main/README.md) | Use expandable host sections so readers can focus on their integration. Keep our normal setup, activation, and updates together. |
| [Addy's documentation skill](https://github.com/addyosmani/agent-skills/blob/main/skills/documentation-and-adrs/SKILL.md) | Preserve repository conventions and record consequential decisions. Its application scaffold is not our installation procedure. |
| [Superpowers README](https://github.com/obra/superpowers/blob/main/README.md) | Make host-specific entrypoints discoverable. This is an example README, not a documentation-writing skill or proof of our behavior. |

Verify host requirements against official host documentation. Example repositories
do not justify copied wording, unsupported commands, or unverified quality claims.
Keep source links and their purpose for substantial comparison-based rewrites;
minor edits do not need a bibliography.
